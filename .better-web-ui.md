## Design Context

### Users

Factory staff, operators, supervisors, managers, and administrators use this bilingual industrial SaaS application to monitor production lines and machine states, record operational changes, configure factory resources, and read reports. The primary interface is a desktop operational dashboard; responsive layouts also support smaller screens and touch use. Keep tasks understandable for staff without technical training.

### Brand Personality

Clear, dependable, and practical. The interface should communicate operational truth and support quick decisions. Keep language direct and use the existing Factory Lean terminology in the English and Arabic dictionaries.

### Aesthetic Direction

Preserve the current visual language. The application uses a light background, white panels, dark navy navigation, a restrained teal primary accent, status colors, compact data views, and modestly rounded controls. Keep information-dense factory dashboards scannable. Do not introduce a new design system or redesign pages as part of setup.

### Implementation Defaults

- **Detected stack:** Next.js 16 App Router, React 19, TypeScript.
- **Detected styling:** Handwritten global CSS in `src/app/globals.css`, imported by `src/app/layout.tsx`, with CSS custom properties, semantic classes, and responsive media queries. Continue using this CSS architecture. Do not add Tailwind or shadcn/ui or replace existing styles.
- **Detected UI structure:** Custom React components in `src/components/` and operational screens in `src/features/`; native HTML forms and tables. Preserve existing component and interaction patterns unless a later task explicitly changes them.
- **Localization:** English and Arabic dictionaries in `src/locales/`; Arabic uses RTL document direction. Check both languages, text expansion, alignment, numeric data, and icon direction in future UI work.
- **Product surfaces:** Production-line and machine-status views, cross-line alternatives, configuration forms, permission-aware actions, reports, tables, and data visualization. Preserve the meaning of physical and production-flow states; UI work must not change business or database logic.
- **Accessibility:** Maintain readable contrast, visible focus states, clear labels, keyboard access, touch-sized controls, and reduced-motion support. Pair status color with text or another explicit cue.
- **Framework guidance:** Read the installed Next.js version-matched documentation in `node_modules/next/dist/docs/` before future Next.js code changes, as required by `AGENTS.md`.

### Design Principles

1. Make line and machine state easy to scan through consistent labels, grouping, and visual priority; never let decoration imply a status the application does not report.
2. Keep dense dashboards usable by aligning repeated data and separating operational groups with spacing and hierarchy before adding visual effects.
3. Use familiar controls and direct language so non-technical factory staff can complete status, configuration, and reporting tasks confidently.
4. Treat English and Arabic, including RTL layout, as equal first-class interfaces on desktop and responsive screens.
5. Preserve accessible feedback and existing interaction patterns while refining the current CSS system rather than introducing a parallel component or styling system.
