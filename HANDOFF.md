## 2. Project Purpose

Factory Lean is a low-complexity, affordable manufacturing operations and Lean SaaS for small and medium factories, initially Jordan and Qatar/Gulf. A plastic-pipe factory is an initial example. It combines production operations, visual lines and machines, stoppage impact, alternative routing and cross-line borrowing, production requests, planning, reports, and continuous improvement. Its differentiator is understandable operational outcomes rather than ERP-style data entry alone. Owners, managers, planners, technicians, HR, and other staff, including non-technical users, must be able to use it.

## 5. Core Production Invariants

- **IMPLEMENTED / CRITICAL:** `evaluateFlow` in `src/utils/production-flow.mjs` is the sole effective production-flow engine. Physical `work_centers.status` is separate. UI mapping in `src/utils/floor-visual.mjs` must only display success when the flow verdict supports it.
- An **open `production_transfer` row is assignment truth**: the alternative stays on the borrowing branch until the transfer ends. Borrowing never changes permanent `line_id`. A stopped alternative remains borrowed and visible, shows its real physical status, and does not end the transfer. The home line keeps its placeholder; the borrowed machine cannot count as home capacity or animate home connectors.
- The approved original-machine transition back to `running` ends its open transfer. The latest return path restores the alternative's prior order assignment only if it still holds the borrowed order; it preserves newer physical states.
- Existing impact modes/scopes include blocking with `whole_line` or `downstream`, `none`/`non_blocking`, `independent`, and timed `buffer`. A stop's impact depends on its configuration. Independent/semi-finished production need not follow one uninterrupted line. Track machine downtime per machine; duration formatting uses minutes or compact hours. Do not collapse all stoppages into a generic factory downtime measure.

## 6. Pause / Resume

- **IMPLEMENTED:** Pause is an intentional operational line state, not a failure. Running home machines become Idle; already Idle and Stopped/Setup/Offline machines keep their physical states. Already borrowed machines are excluded. The private `line_pause_auto_idled` table records which machines the pause changed.
- Resume restores only tracked machines still Idle and not borrowed. A later manual status change clears the marker, so Resume does not overwrite it. A paused line can release an eligible Idle configured alternative for borrowing, including one tied to a different home order.
- When a borrowed machine returns while its home line remains Paused, a Running alternative becomes Idle; a real Stopped/Setup/Offline state remains truthful. Return after home Resume is governed by actual status and `evaluateFlow`. The return path preserves the original pause marker when appropriate.

## 7. Categories / Alternatives / Capabilities

- **IMPLEMENTED:** Each work center has `category_id`, a compatibility family. Same category makes an alternative eligible but never configures it automatically; an explicit `work_center_alternatives` row is required. Cross-category transfers and alternatives are rejected, and category edits cannot strand incompatible relationships. Cross-line relationships are allowed.
- `CenterAlternatives.tsx` calls only `configure_center_alternatives`; that RPC writes only `work_center_alternatives` after factory, permission, existence, and category checks. `CenterCapabilities.tsx` separately calls `configure_center_capabilities` to write `work_center_capabilities`. Saving alternatives must never send, delete, reconstruct, or overwrite capability rows.

## 9. Production Requests / Orders

- **IMPLEMENTED (committed `1c324f8`, pushed to `origin/main`):** One business `production_requests` header contains multiple `production_orders` product items.
