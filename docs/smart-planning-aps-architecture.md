## Proposed relationships and workflow

Keep one application and database. Introduce an advisory computation over existing authoritative records as needed within the approved APS implementation. Bound horizon, input size and unknown data. Compare an explainable deterministic reference candidate with other feasible sequences before evaluating any solver choice. There is no selected algorithm or approved scoring policy.

```text
Sales order lines | Required replenishment | Optional run opportunities
           -> Demand coverage by product specification and unit
           -> Existing production request -> One or more scheduled Product Items
           -> Actual line runs -> Recording -> Quality -> Warehouse receipt
           -> Customer or stock allocation evidence -> Shipment where applicable

Current demand, capabilities, calendar, Maintenance, supply and dated policies
           -> Scoped input snapshot -> Proposed schedule and comparison
           -> Explicit approval -> Protected Scheduling commands -> Plan revisions

Approved plan + revised plan + actual runs + evidenced assumptions
           -> Existing Lean comparison and future F37 views
```

- A coverage relationship links demand to items and records the intended quantity, unit, source and priority basis. Customer reservations, receipts and dispatch remain authoritative as physical work progresses. For split runs, total child coverage across all items cannot exceed remaining demand. Reuse amount and audit identities where they already represent the same event. Store only relationships and evidence the current model cannot express.
- A proposed plan would capture the baseline revision, input scope/as-of, rates, setup rules, recipe versions, material/time assumptions, constraints and affected demand. Recheck permissions, current input revisions, conflicts and commitments when applying. An approved batch needs atomic revalidation or a clearly reviewed, individually confirmed sequence of existing commands with dependent changes kept together. The current item writer is insufficient evidence that arbitrary multi-item application is atomic. Retry must reconcile the exact intent. Prevent any duplicate apply, duplicate coverage or optimistic committed display.
- Resolve need and availability per unit and date. Apply the approved receipt-time reservation and Planning/Sales reallocation rules. For the initial trial, require identical specifications and the same verified recipe revision. In APS 2, an authorized Planning override affects an optional economic minimum only. Equipment limitations and valid increments remain binding. Treat setup and recovery as evidenced resource intervals. Apply the most specific approved rule and flag unresolved conflicts. Schedule setup sequentially unless explicitly configured and approved to overlap with available resources and prerequisites satisfied. Keep proposed holds and assumed ETAs distinct from confirmed reservations and actual events.
- Allow authorized Production engineers to approve and version setup and restart standards directly, retaining effective dates, permissions and audit history. Record initial line-specific engineering estimates as estimates and use operational evidence to improve them.
- Keep the financial event time separate from warehouse arrival and issue. Use the approved factory cost method or weighted-average default, base accounting currency, and one cost lineage through purchase ownership, physical receipt and conversion to WIP and finished goods. On-hand and owned in-transit can contribute to current value. Other confirmed inbound purchases are projected from expected ownership transfer. Carry uncertainty and Accounting-approved estimates as evidence and withhold a mandatory compliance result when material costs remain unknown.
- Record the proposed before/after buffer and impact for each affected customer. In the first trial an authorized planner reviews justified buffer use case by case. The approval event should capture the customer impact and reason alongside the plan revision.
- Separate recommendation, protected approval and actual execution. Store original and changed approval snapshots for future reporting. Plan version edits do not silently change actual routing, stock or initiation. Apply the approved configurable defaults of 12 hours for operational protection and seven days for the financial transition. They govern distinct checks. Preserve the policy effective date and forecast across it. An unknown required input produces an explicit unverified or blocked result for the applicable constraint.

## Official product references and bounded adaptations

- **frePPLe Plan Editor.** It provides distinct feasibility, criticality and delay views with selectable Gantt detail. Use parallel concepts to explain material shortages, lack of slack and lateness in Factory Lean. Keep the default to one clear recommendation. [frePPLe documentation](https://frepple.com/docs/current/user-interface/plan-analysis/plan-editor.html)
- **MRPeasy Production Schedule.** Its schedule uses Gantt/calendar views, drag-and-drop and order drill-down. Reuse Factory Lean’s existing gesture and drawer so a planner can inspect work without learning a second editor. [MRPeasy user manual](https://www.mrpeasy.com/resources/user-manual/production-planning/production-schedule/)
- **SAP PP/DS.** Pegging links demand to relevant stocks and receipts and can expose coverage problems. Sequence-dependent setup is a detailed scheduling concern. Adopt traceable demand coverage and directed setup rules with a compact factory-specific rule set. [SAP pegging](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/f899ce30af9044299d573ea30b533f1c/02e4ab50135e0c0be10000000a423f68.html) · [SAP detailed scheduling](https://help.sap.com/docs/PRODUCT_ID/f899ce30af9044299d573ea30b533f1c/4c6af71b832821d1e10000000a42189c.html?locale=en-US&state=PRODUCTION&version=latest)
- **Siemens Opcenter APS.** Siemens describes what-if evaluation, finite scheduling and visibility of competing resource constraints. Use on-demand breakdown/replanning alternatives and explain resource impact at the point of choice. [Siemens Opcenter APS overview](https://static.sw.cdn.siemens.com/siemens-disw-assets/public/5eYtkPmCgY7grKmOYrplWg/en-US/Siemens-SW-Using-Opcenter-APS-to-optimize-planning-Infographic_tcm27-102601.pdf)

These are product-design references. Their features do not establish Factory Lean approval or implementation scope.
