# F45 — product creation and configuration

Implemented and verified locally on 17 November 2026; owner acceptance and Git checkpoint pending.

The four-section Add/Edit dialog uses one atomic, authenticated save and the existing product, BOM, material-source and work-center capability records. product_configuration_context supplies a current edit fingerprint and exact numeric input strings. save_product_configuration rechecks factory-scoped per-person Orders create/edit and Centers edit for capability changes, serializes factory/Maintenance/structure admission, rejects stale edits and records its actor/intent-bound fulfillment command. Committed UUID replay returns the same product; ambiguous transport outcomes retain the exact stored intent and recover its receipt. Never issue a replacement save identity while its outcome is unknown. A failed line/recipe validation rolls back the entire product/compound/BOM save and receipts.

Product code is automatically generated when blank on creation; existing blank code retains the identifier. Existing unique(factory_id,code) remains authoritative. Category is optional. The form does not rewrite supply settings, thresholds, historical identifiers or stock balances.

Inline recipes use the same versioned bom_versions/bom_items model directly on the finished product; reusable recipes retain the existing manufactured-intermediate identity. Each version declares its batch_quantity kg output, with kg ingredients, unique RAW_MATERIAL identities and nonnegative existing forecast allowances. The default new batch is 1 kg; old batches remain explicit and unchanged when editing. Existing requirements, forecast and actual-consumption calculations continue to divide ingredient quantities by that batch basis. A product-only recipe may also be found through a cut-length base product while its per-piece weight remains authoritative. Shared recipes are selected without mutation; editing one that other products use is blocked in this form and suggests a product-specific recipe. Preserve historical BOM versions and frozen recording factors.

Weight basis is nullable for legacy records and never backfilled. For a declared STOCK_UNIT measurement, unit_weight_kg is the measured kg for that stock unit. For PIECE plus meter stock, it is measured kg / positive length in meters. For piece stock it is the piece weight, regardless of physical length; kg intermediates use 1 kg/kg. Browser values are previews; SQL numeric arithmetic is authoritative. Exact decimal text crosses the browser for existing weights, dimensions, ingredient quantities and rates. Stock identity guards, historical-weight protection and immutable cut-length identities remain. Do not infer the meaning of old untyped weight/length values.

Line eligibility is an interface over machine capability records, not a new line/product table. Users explicitly choose real categorized production machines and a rate in production units per hour. The existing machine writer owns constraints, audit, child cut-length rate derivation and Maintenance invalidation. Other products and setup times survive; unassigned equipment settings are retained. Active participating capabilities cannot be removed or changed; actual Start/transfer still validates complete routing, equipment roles, availability, materials and permission. No manual configuration alone promises an entire line is physically ready, changes an approved plan or starts production.

Complete inline/saved recipes reuse the current physical input source, or use the displayed direct-raw default for a new product. Switching a premixed-stock product to a product-only raw recipe requires an explicit raw-source choice; stage-specific source definitions remain untouched and visible as a warning. Incomplete products have no new workflow status: existing readiness guards prevent production until their required definitions exist. Existing supported stock units remain unchanged; arbitrary new stock-unit families are outside F45.
