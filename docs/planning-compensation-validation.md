The source itself was already excluded. It now uses half-open interval overlap for actual PLANNED reservations and conservatively blocks another ACTIVE job. Capacity includes the original ordinary remaining work plus existing executable allowance and the proposed new quantity. 4. **Silent rerouting:** the reader previously set planned_fallback and the UI sent PLANNED for an active execution. SQL independently rejects a new PLANNED decision against an active source with output_active_execution; a modified client cannot bypass this. 5. **Explicit actions:** active source = Add Compensation to Current Execution; ended source = Create Make-Up Production Work. The UI shows active/ended state, rejected quantity, unallocated shortage and existing linked decisions. A genuine conflict retains active identity, identifies the order/time and directs authorized Planning review or a smaller quantity if genuinely feasible. No automatic work or demand increase.
