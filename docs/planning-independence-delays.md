# F46 — Planning independence and actual production delays

Implemented locally on 18 November 2026; owner acceptance and hosted alignment remain pending.

Planning reserves the approved `line_id`, `start_time` and `expected_finish`. Unknown actual finish, overdue active work and a bare equipment stop are advisory; they never implicitly extend a Planning reservation. Genuine approved overlaps, capability/unit/calendar restrictions and Maintenance reservations/holds remain protected. Actual execution still admits at most one active order per actual line. F20 actual location remains `coalesce(actual_line_id,line_id)`; no execution transfer or delay action rewrites Planning.

The protected operational board has an explicit `production_plan` domain for Production Planning. Its production occupancy follows approved intervals. The existing `all` / Maintenance domain keeps conservative actual occupancy and existing Maintenance admission rules. Active legacy work with a missing approved window is an explicit warning, not an indefinite production-plan reservation; genuinely invalid Maintenance windows remain rejected.

Floor displays **Behind Schedule** immediately after an unfinished active order passes its approved finish, with elapsed delay. Planning displays the same actual delay and potential affected planned work. Warnings do not move any planned bar or claim a forecast is a commitment.

The owner-approved default grace period is **15 minutes**, factory configurable under Planning → Custom date range and zoom. Orders view can read it; factory edit is required to change it. Authorized Orders edit staff record a meaningful reason and optional future revised estimated completion inline with the order. At the grace boundary an unrecorded reason stays visibly pending. There is no repeated prompt, automatic stop, recording/Start restriction or future-scheduling restriction because of a missing reason. An elapsed estimate is advisory and does not automatically demand another reason.

`private.production_delay_policy` stores only explicit factory changes; existing factories read the approved default without a backfill. `private.production_delay_events` appends server actor/time, reason, optional ETA, original approved finish/revision, actual line, grace and order snapshot. Update/delete is rejected. The episode binds item and approved revision/interval; Pause/Resume/actual-line transfer alone does not create a new obligation or erase evidence. An explicit later Planning revision creates a separate episode. The most recent reason in the current episode clears pending status, while all prior events remain in history. The UI shows the latest 20 history events and total count; full evidence stays in the database for future F37.

`production_delay_read` and `production_delay_command` enforce factory/person permissions. Writes share existing factory/accounting admission locks, recheck the order and fingerprint, and use actor/intent-bound command UUIDs. Exact committed retries return once. Stale concurrent changes reject. An ambiguous response retains the exact intent locally and reconciles its receipt; it cannot claim success or generate an automatic replacement request. Reason/ETA writes never change an order, stock/reservation/consumption, plan revision or production history. Policy changes use existing audit records. Private tables have no client DML privileges and RLS is enabled.
